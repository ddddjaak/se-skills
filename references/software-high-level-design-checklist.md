# Software Development Checklist

## 检查清单 (CheckList)

### 检查项概览

| 编号 | 检查项 |
|------|--------|
| 1.0 | Configuration Items Check（过程域配置项检查） |
| 2.0 | Basic Information Check（基本的信息检查） |
| 3.0 | Architecture Chart Check （需求概述检查） |
| 4.0 | Interface Design Check （接口设计检查） |
| 5.0 | Design Check（设计检查） |

### 1.0 Configuration Items Check（需求过程域配置项检查）

| 编号 | 检查内容 |
|------|------|
| CIC1 | 是否有沟通记录 |
| CIC2 | 是否有接口需求规范(Optional，如不需要请备注) |
| CIC3 | 是否有概要设计输出(在线系统承载或线下文档) |
| CIC4 | 是否有FOSS评估报告 (Optional ，若涉及，需提供 ) |

### 2.0 Basic Information Check（基本的信息检查）

| 编号 | 检查内容 |
|------|------|
| BIC1 | 概要设计文档需要包含模块需求概述、模块架构设计、软件静态设计、软件动态设计、接口设计、设计约束等主要章节描述。 |
| BIC2 | 需要描述软件概要信息，包含主要功能，性能，主要接口等 （相当于软件简介） |
| BIC3 | 概要设计输出物的版本是否记录清晰？ |
| BIC4 | 对于使用的到开源组件，是否有明确的说明 |

### 3.0 Requirements Overview Check （需求概述检查）

| 编号 | 检查内容 |
|------|------|
| ROC1 | 承接的需求是否描述完备 |

### 4.0 Interface Design Check（接口设计检查）

| 编号 | 检查内容 |
|------|------|
| IDC1 | 接口设计检查： - 需要描述软件外部接口 - 函数接口可按模块罗列。 |
| IDC2 | 接口描述检查：要素是否完备 |
| IDC3 | 接口时序图检查： - 需要包含主要的功能 -从时序图判断设计是否存在冲突、冗余等问题 |

### 5.0 Design Check （设计检查）

| 编号 | 检查内容 |
|------|------|
| DC1 | 架构设计是否合理，是否清晰展示软硬件架构关系 |
| DC2 | 源文件描述是否清晰，完备 |
| DC3 | 头文件引用关系图是否表达准确无误 |
| DC4 | 动态设计： - 有展示软硬件功能流转图 -清楚描述运行模式、进程通信、中断等关系 |
| DC5 | 设计约束检查： - 硬件约束 - 时间约束设计 -性能约束设计 -内存使用设计 |
