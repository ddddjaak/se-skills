# 方案架构设计 Checklist

## 检查清单 (CheckList)

### 检查项概览

| 编号 | 检查项 |
|------|--------|
| 1.0 | 文档基础信息 |
| 2.0 | 需求来源检查 |
| 3.0 | 系统概述检查 |
| 4.0 | 系统架构设计检查 |

### 1.0 文档基础信息

| 编号 | 检查内容 |
|------|------|
| 1.1 | 标题与版本号：是否明确标注文档标题、版本号、发布日期？ |
| 1.2 | 方案版本变更：是否记录清晰？修订记录是否有？ |
| 1.3 | 方案承接需求：是否条目化？ |
| 1.4 | 术语表：是否定义专业术语、缩写和符号？ |
| 1.5 | 如有特殊需求是否已标注出来？ |

### 2.0 需求来源检查

| 编号 | 检查内容 |
|------|------|
| 2.1 | 方案承接的每条需求是否都清晰标注来源？ |

### 3.0 系统概述检查

| 编号 | 检查内容 |
|------|------|
| 3.1 | 项目背景：是否说明项目的背景、需求和目标？ |
| 3.2 | 功能需求：是否列出系统核心功能（与需求文档一致）？ |
| 3.3 | 非功能需求：是否涵盖性能、功耗、实时性、安全性、可靠性等要求？ |
| 3.4 | 系统边界：是否明确系统与外部设备/环境的交互关系？ |

### 4.0 系统架构设计检查

| 编号 | 检查内容 |
|------|------|
| 4.1 | 总架构图：是否有清晰的架构框图？ |
| 4.2 | 硬件架构图：是否有且清晰？ |
| 4.3 | 软件架构图：是否有且清晰？ |
| 4.4 | 模块划分：是否划分核心模块（如传感器、通信、存储、处理单元等）？ |
| 4.5 | 模块职责：是否定义每个模块的功能和职责？ |
| 4.6 | 关键子场景：是否描述清楚了关键子场景逻辑？ |
| 4.7 | 关键子场景：是否描述清楚了关键子场景的数据交互方式？输入输出要求？ |
| 4.8 | 关键子场景：如果有核心算法设计，是否描述清楚了核心算法？ |
| 4.9 | 协议设计：是否描述清楚了协议内容，包括帧格式、时序要求，以及数据ID定义是否清晰？ |
| 4.1 | 协议设计：如果由单独文件承载协议详情，是否提供相关协议文件？ |
| 4.11 | 工具：是否有且清晰？ |
