# Software Development Checklist

## 检查清单 (CheckList)

### 检查项概览

| 编号 | 检查项 |
|------|--------|
| 1.0 | Configuration Items Check（过程域配置项检查） |
| 2.0 | Basic Information Check（基本的信息检查） |
| 3.0 | Detail Design Rule Check（详细设计检查） |

### 1.0 Configuration Items Check（需求过程域配置项检查）

| 编号 | 检查内容 |
|------|------|
| CIC1 | 是否有沟通记录 |
| CIC2 | 是否有详细设计输出 ( 在线系统承载或线下文档 ) 和模块单元 |

### 2.0 Basic Information Check（基本的信息检查）

| 编号 | 检查内容 |
|------|------|
| BIC1 | 文档描述是否包含编写目的、项目背景、缩写词定义、专业术语定义、参考资料？ |
| BIC2 | 架构设计输出物的版本是否记录清晰？ |

### 3.0 Detail Design Rule Check（详细设计检查）

| 编号 | 检查内容 |
|------|------|
| DRC1 | 是否使用图表的方式对模块内部结构进行定义，且分解到文件和函数级别，体现出函数的调用关系。 |
| DRC2 | 模块设计是否满足如下设计原则：高内聚，低耦合，通用功能设计，服从命名规则。 |
| DRC3 | 功能概要是否体现该软件模块所有的函数，包括函数名称，函数功能。 |
| DRC4 | 功能概要是否体现如下全局信息：数据类型，全局变量，宏符号。 |
| DRC5 | 函数详细设计是否清晰定义函数传入参数的名称、含义、数据类型、取值范围，以及返回值的类型、含义、取值范围。 |
| DRC6 | 函数详细设计是否体现函数实现逻辑的流程图（逻辑简单的函数可忽略） |
| DRC7 | 如果软件单元之间有状态转换、顺序调用、消息序列等动态行为，是否有体现 |
